# 主数据管理系统 运维与部署指南

> 版本：v1.0 ｜ 日期：2026-09-30 ｜ 编排架构：Docker Compose + Nginx + FastAPI + PostgreSQL

---

## 1. 系统架构与环境说明

本系统采用轻量单体微架构设计，前后端分离，内置进程级定时调度器与高可用写入管道：

- **前端**：React 18 + TypeScript + Vite + Tailwind CSS + shadcn/ui，由 Nginx 托管静态资源并反向代理 API；
- **后端**：Python 3.12 + FastAPI + SQLAlchemy 2.0 + APScheduler（内建守护线程）；
- **数据库**：PostgreSQL 16（生产环境） / SQLite 3（开发测试环境，零依赖自洽）。

### 服务端口划分

| 服务名称 | 容器内端口 | 宿主机默认端口 | 用途 |
|----------|:----------:|:--------------:|------|
| `frontend` | 80 | 80 / 5200 (本地开发) | 前端静态站点及反向代理网关 |
| `backend` | 8090 | 8090 | FastAPI RESTful 业务引擎及 Open API |
| `postgres` | 5432 | 5432 | 生产持久化关系型数据库 |

## 2. 生产环境快速部署 (Docker Compose)

### 2.1 环境准备
- Docker Engine >= 24.0.0
- Docker Compose >= 2.20.0

### 2.2 部署步骤

1. **克隆项目到服务器部署目录**：
   ```bash
   git clone https://github.com/jack571754/mdm-system.git
   cd mdm-system
   ```

2. **配置生产环境变量**：
   ```bash
   cp .env.example .env
   # 按需修改 .env 中的 JWT_SECRET 和数据库密码
   ```

3. **一键构建并启动服务集群**：
   ```bash
   docker compose up -d --build
   ```

4. **检查容器运行状态**：
   ```bash
   docker compose ps
   ```

5. **验证服务健康度**：
   - 前端 Web 访问：`http://<服务器IP>/`
   - 后端健康检查：`curl http://<服务器IP>:8090/health`
   - Swagger API 文档：`http://<服务器IP>:8090/docs`

## 3. 本地开发与调试指南

### 3.1 后端启动 (PowerShell)
```powershell
cd backend
.venv/Scripts/python.exe -m app.db.init_db   # 校验并初始化种子数据
.venv/Scripts/uvicorn app.main:app --reload --port 8090
```

### 3.2 前端启动
```bash
cd frontend
npm install
npm run dev
# 访问本地前端开发服务器：http://localhost:5200
```

### 3.3 自动化测试执行
在 `backend` 目录下执行全量单元与集成测试：
```bash
.venv/Scripts/python.exe -m pytest tests -v
```

## 4. 常见运维操作与故障排查

### 4.1 数据备份与恢复
- **Postgres 备份**：
  ```bash
  docker exec -t mdm_postgres pg_dump -U mdm_user mdm_db > backup_$(date +%Y%m%d).sql
  ```
- **Postgres 恢复**：
  ```bash
  cat backup_*.sql | docker exec -i mdm_postgres psql -U mdm_user -d mdm_db
  ```

### 4.2 查看日志
- 后端实时日志：`docker compose logs -f backend`
- 同步引擎与调度日志：`docker compose logs backend | grep "[Scheduler]"`
- Nginx 访问与代理日志：`docker compose logs -f frontend`

### 4.3 待确认删除误判恢复
若上游数仓由于网络波动误删导致记录被标记为 `pending_delete = True`：
- 管理员可在系统界面「数据治理」->「数仓同步中枢」中，勾选对应记录并点击「忽略并保留」即可一键恢复，全程留痕可对账。
